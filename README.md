# 第二大脑 · Second Brain

一套由 LLM 持续维护的常驻知识库。不是「把资料丢进去、用的时候再搜」的收藏夹，
而是**让 AI 把每一份新材料编译成互相链接的 wiki 页面**，长期累积成一张可读、可查、
可回溯的知识网络。

设计来自 Andrej Karpathy 的 [LLM Wiki](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)
概念：不去原始文档里现查，而是维护一份一直在进化的 wiki。

---

## 为什么不用 RAG

大多数「个人知识库 + AI」的方案是 RAG：切块、向量化、提问时检索片段。
它适合海量、无结构、只读的语料，但对个人知识库有两个硬伤：

- **每次提问都在重新理解**，昨天想通的东西，今天再问一遍还得再推一遍
- **没有沉淀**，检索到的片段是孤立的，不会自动长成结构化的认识

这套方案换了个方向：**用编译代替检索**。新材料进来时只做一次加工，
把结论、关系、矛盾点写进 wiki 页面。之后提问直接读 wiki，而不是读原文。
加工成本前置，收益在后面每一次查询里复利。

代价也很明确：**必须持续维护**。没有新素材时它不会自己长大，
素材进来后不加工就等于没进来。

## 三层结构

| 层 | 目录 | 内容 | 谁写 |
|---|---|---|---|
| **原始层** | `second-brain/raw/` | 网页、文章、视频转写的原样副本，**不可变** | 人（剪藏工具） |
| **Wiki 层** | `second-brain/wiki/` | 摘要、概念、实体、工具、综述 | **只有 AI 写**，人只读 |
| **Schema 层** | `second-brain/agents.md` | 结构约定与工作流 | 人和 AI 共同演进 |

第三层是这套系统真正的「源代码」。换一个 agent、换一台机器，只要它读了
`agents.md`，产出的东西就是一致的 —— 这是让 LLM 成为「守规矩的 wiki 维护者」
而不是通用聊天机器人的关键。

## 怎么用

### 1. 看

用 Obsidian「打开文件夹作为库」指向 `second-brain/`。这一步是可选的 ——
所有内容就是普通的 markdown 文件，任何编辑器都能读。装 Obsidian 的额外好处是
双向链接和 graph view，能直观看到页面之间的连接密度。

### 2. 存

浏览器装 Obsidian Web Clipper，导入 `obsidian插件模版/网页内容获取-clipper.json`，
把剪藏的保存位置指到 `second-brain/raw/`。存进来的东西**永远不修改、不删除、不移动** ——
它是所有 wiki 内容的事实来源。

### 3. 问

对着 agent 说人话就行：

| 你想要的 | 说什么 |
|---|---|
| 存一篇网页 / 视频 | 「把 `<URL>` 存进第二大脑」 |
| 把新素材加工成 wiki | 「处理 raw 里没处理的文件」 |
| 查知识 | 「问一下第二大脑：`<问题>`」 |
| 给库做体检 | 「给这个库做一次 lint」 |
| 改系统行为 | 直接改 `agents.md` |

### 四个核心动作

- **ingest** —— 读 `raw/` → 建来源页 → 更新受影响的实体/概念/工具页 → 登记 `index.md` → 追加 `log.md`
- **query** —— 先读 `index.md` 定位 → 读相关 wiki 页作答 → 可复用的知识回写成新页面
- **lint** —— 找矛盾说法、被推翻的旧结论、孤儿页、缺页的重要概念、缺失的交叉引用
- **evolve** —— 加新目录（`crm/`、`journal/`），然后在 `agents.md` 里写清它的规则

## 写作约定

每条 wiki 页面必须带 front matter：

```yaml
---
type: source | concept | entity | tool | synthesis
title: ...
sources: ["对应来源页的标题"]
updated: YYYY-MM-DD
---
```

三条硬规则：

1. **忠实原文** —— 来源没说的不写，不臆造
2. **不能有孤儿页** —— 新页面必须链回它的来源页
3. **相对路径互链** —— 用 `[[wiki/entities/xxx]]` 这种形式，Obsidian 的 graph 才有东西可看

`log.md` 的每条记录固定以 `## [YYYY-MM-DD] 动作 | 标题` 开头，
所以取最近几条只需要一句 `grep "^## \[" log.md | tail -5`。

`index.md` 一份目录就够了，不需要向量检索基础设施**。要加检索的时候，
是在 wiki 之上叠一层（如 [`qmd`](https://github.com/tobi/qmd)），不是替换 wiki。

## 扩展方向

- 想记人 → 加 `crm/`
- 想记日记 → 加 `journal/`
- 想丢失的上下文 → 加 `journal/`，让 agent 每天读一遍
- 想远端备份 → 给这个仓库加一个 remote
- 库大到 `index.md` 读一遍都费劲 → 加本地搜索引擎

改 `agents.md` = 改整个系统的行为。描述得越精确，它才越像你想要的样子。
